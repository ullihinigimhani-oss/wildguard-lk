2. **Blue approach route.** Existing POST `/api/navigation/route` continues to route real foreground GPS to the current next destination. Before START is reached, that destination is START and the line is blue.
3. **Green full route.** New GET `/api/navigation/patrols/:patrolId/route` loads saved PatrolWaypoints and requests a foot-walking route from START through every required point to END. Only real provider geometry is drawn.
4. **Manager order.** Saved points are loaded by ascending `order`; the full saved sequence must be valid and consecutive. Required destinations retain this exact order. Provider waypoint indices are validated before splitting geometry for display.
5. **HIGH_RISK.** Excluded from routing coordinates only. Its existing red warning marker remains in the map document; live progression remains unchanged.
6. **Risk avoidance.** Both route requests use the existing authoritative park RiskZone service and Polygon/MultiPolygon `avoid_polygons`. Active HIGH/CRITICAL filtering is unchanged. Every mandatory destination is checked before full routing. Returned geometry and intermediate off-network waypoint connectors are checked for risk intersections.
7. **ORS request strategy.** One multi-coordinate request, with `instructions: false`, using the existing HeiGIT foot-walking GeoJSON endpoint. No per-leg provider requests. Routes with more than 50 required destinations return a clear unavailable state rather than truncating them. This follows the [provider waypoint limit](https://openrouteservice.org/restrictions/).
8. **Green cache.** Separate process-local full-route cache, valid for 10 minutes, keyed by patrol, all required waypoint definitions and trusted RiskZones. The live cache retains its existing 45-second policy. Cache reads do not consume provider quota. Identical pending requests coalesce. Both types share the original 10-second server cooldown, six calls/minute per Ranger, 30 process-wide calls/minute, single pending request per Ranger and 15-second timeout. Mobile reuses the full result across GPS updates and progression, and invalidates it when the patrol session, waypoint coordinates/order/type or known risks change. Initial live routing takes priority. Only HTTP 429 receives up to three delayed automatic full-route retries; other failures require explicit retry. These budgets remain process-local, as before.
