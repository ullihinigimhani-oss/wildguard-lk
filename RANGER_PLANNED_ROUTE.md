# Ranger mobile — first planned patrol-map phase

Implemented on `feature/ranger-patrol-incident-management`.

1. **Files changed:** Added `mobile/src/screens/patrol/PatrolRouteScreen.js`, `hooks/useAssignedPatrol.js`, `utils/plannedPatrolRoute.js`, and `components/patrol/{PatrolRouteMap.js,PatrolMapSurface.js,PatrolMapSurface.web.js,plannedMapDocument.js,PlannedRouteSummary.js}`. Updated PatrolDetailsScreen, AppNavigator, linking, mobile package/lockfile, and navigation/detail tests. Added planned-route utility/screen tests and test-only route fixtures. Extended the existing backend patrol lifecycle API test with read-only route/ownership/GPS-write assertions. Backend production code and manager web code were unchanged.
2. **Map library:** Leaflet 1.9.4 and real OpenStreetMap HTTPS tiles, inside an isolated native WebView; the Expo web preview uses the same document in a sandboxed iframe. This does not try to render React-Leaflet directly in React Native. Attribution remains visible. Leaflet CDN assets are version-pinned and integrity-checked. Tile policy: https://operations.osmfoundation.org/policies/tiles/ . Map data requires connectivity; failure retains the native route list and provides Retry map.
3. **New dependency:** Only `react-native-webview` 13.16.1, exactly matching Expo 57's locally installed `bundledNativeModules.json` recommendation. Expo documents it as included in Expo Go: https://docs.expo.dev/versions/latest/sdk/webview/ . Existing Expo ~57.0.25 and React Native 0.86.3 are retained. No Google Maps billing key or native Google Maps dependency. Leaflet runs in the map document, so no additional native mapping library is needed.
4. **Fetching:** My Patrol still opens existing Patrol Details. View Route navigates with only the selected patrolId. The nested screen re-fetches `GET /api/patrols/mine/:patrolId` through the existing Axios API client and session Authorization setup. Focus/retry loading is abortable and ignores responses after blur/unmount or identity changes. No cached navigation payload or hardcoded Ranger/Patrol ID substitutes for authenticated retrieval. Unauthorized/unavailable/network messages are sanitized.
5. **Waypoints:** Copies and sorts by persisted integer order, preserving original coordinates. Renders START, CHECKPOINT, HIGH_RISK, OBSERVATION and END. Real names and notes appear in both marker popups and the ordered native list, with type-based fallbacks only when labels are absent. Old records show No Planned Route. Invalid types/coordinates/order are handled safely and show an incomplete-route warning.
6. **Checkpoint numbering:** Checkpoints receive 1, 2, 3… in saved sequence, independent of the other types. Invalid checkpoint coordinates retain their position in the numbering sequence, so other saved checkpoint numbers do not silently change. Custom names remain intact.
7. **High risk:** Red `#b42332` warning marker with `!`, red High Risk Area popup heading, and tinted native list row. Stored custom names and notes remain available. This is display of the manager's HIGH_RISK waypoints; no polygon generation or avoidance occurs.
8. **Observation:** Purple `O` marker with a distinct shape and Observation Point label, custom name and note.
9. **Polyline/camera:** Dashed green lines connect the saved coordinates in order. Initial bounds show the complete valid route; Fit Route repeats that action. A single valid point centers at an appropriate zoom. Malformed points or sequence gaps break the line rather than inventing a shortcut. Map gestures, pan and zoom are supported. Markers are read-only.
10. **Distance:** Backend currently returns ordered route points rather than a stored distance. Mobile derives Approx. Planned Distance with the same Haversine formula/mean Earth radius (6371.0088 km) as the manager planner. Labels explain direct geographic segments may differ from terrain/road/trail travel. Incomplete routes suppress the distance rather than show a misleading total. Counts derive from displayed saved data.
11. **Authorization:** Existing middleware and rangerId ownership predicates remain unchanged. The backend test verifies ordered, restricted-field route selection; Ranger B receives no route; GET makes no lifecycle/GPS writes. An additional read-only verification used an existing real saved six-point patrol: assigned Ranger received HTTP 200 and a different approved Ranger received HTTP 404. No verification users, patrols, waypoints or GPS records were created or changed.
12. **Database/schema:** No schema edit, migration, reseed or database write. PatrolWaypoint remains manager-planned data; PatrolLocation remains reserved for future actual GPS samples. DATABASE_URL and ORS_API_KEY were unchanged. `backend/.env` is Git-ignored and untracked.
13. **Backend tests:** 277 tests passed across 13 suites, including manager creation/atomic waypoint validation and lifecycle/ownership regressions.
14. **Mobile tests:** 132 tests passed across 16 suites. Coverage includes mixed point types, numbering, red warning presentation, notes, empty/single/malformed routes, coordinate immutability, distance, map load/retry, sanitized request errors, nested navigation/deep links, separate View Route/Start actions and unchanged four tabs/lifecycle behavior.
15. **Builds/rendering:** Android Hermes export passed (934 modules), Expo web export passed (611 modules). Manager web's 92 tests and production build passed. Existing manager build has its bundle-size advisory. The identical mobile map document was visually reviewed at 390×360 using the existing saved route: fitted points, checkpoint symbols, red High Risk popup, real tiles and attribution rendered with zero console errors/warnings. Android compilation and native wrapper behavior were checked; a physical-device or emulator gesture smoke test was not performed in this environment. Temporary preview HTML was removed and its local server stopped. [Verified phone-size map preview](<C:/Users/Lihini/Desktop/WildGuard LK/wildguard-lk/mobile/.expo/patrol-route-map-preview.png>).
16. **ORS secret safety:** Compared the configured backend secret in memory against 131 client source/export/environment files, including the Android Hermes and web exports: no match. The key was never printed, included in map HTML/headers, or added to EXPO_PUBLIC settings. There are no client calls to ORS. Native document navigation is restricted; manager labels/notes are serialized safely and rendered through text nodes. No session token enters the document.
17. **Deferred:** ORS walking navigation, safe-route generation, risk-polygon avoidance, current GPS location, continuous tracking, visited checkpoints, actual trail storage and planned-versus-actual comparison. No location dependency or permission was added; WebView geolocation is disabled. The planned map layer is isolated so future current-location/actual-trail layers can be added separately. Opening View Route never starts/completes a patrol. Existing Start/Complete actions remain on Patrol Details, and Dashboard/My Patrol/Report Incident/Profile remain the only four main tabs.
